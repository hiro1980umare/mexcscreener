# 研究報告書: 米国株「Quality × Timing」スクリーニングの検証

**版: 1.0 / 作成: 2026-10-09 / 結論: この方法では、全銘柄を等金額で持つ方法を上回る優位性を示せなかった**
（「優位性がない」という証明ではない。第8章の限界を必ず併せて読むこと）

---
## 1. 要旨
- 目的: 「業績・財務が良い企業が、短期的な調整で売られ、押し目になっている銘柄」を機械的に抽出する方法に、**過去データで検証できる優位性**があるかを確かめる。
- 方法: 過去の各時点で**その時点までに公開されていた情報だけ**を使って銘柄を判定し、その後の1・3・6か月の成績を、全銘柄を等金額で持つ方法(ALL_GATE)、RSIだけの方法(SIMPLE_RSI)、SPYと比べた。
- 結果: 3つのルール版(V1: 技術指標のみ / V2 / V2b)のどれも、**事前に登録した基準を満たさなかった**。最も重要な検証(Quality高×Timing高 vs 全銘柄、3か月後)の差は、V2が +0.33%（区間 −0.87〜+1.51%）、V2bが −0.30%（97.5%区間 −1.65〜+1.06%）で、どちらも0と区別できない。
- 試した版: dev期間(2017年以降)で試したルールは **V2とV2bの2版だけ**（V2cは作らない）。V1は技術指標だけの前段階。
- **2011〜2016年の最終検証期間は、一度も使用していない**（株価データも取得していない）。
- 結論: 「**この方法では優位性を示せなかった**」。ただし検出力に限界があり（第8章）、「優位性がない」とは言えない。
- 位置づけ: 優位性が示せなかったため、通知Botは「**候補リスト・監視ツール**」として運用し、「勝てる」「高確率」などの表現は使わない（第9章）。

---
## 2. 問いと検証デザイン
**問い**: 「Quality(良い会社) × Timing(押し目)」は、全銘柄保有や、RSIだけの方法より、意味のある差を出せるか。

| 項目 | 内容 |
|---|---|
| 対象 | NASDAQ/NYSE上場の普通株。ETF・ワラント・優先株等は除外。現在の時価総額$300M以上を取得対象とし、各基準日に下のGateを適用 |
| Gate | 当時の実際の株価(分割調整前)$5以上 / 当時の時価総額$1B以上 / 50日平均売買代金$10M以上 |
| 時価総額(V2以降) | 「当時の株価(分割調整前) × 基準日より前に提出された10-K/10-Qの発行済株式数」。株式数が取れなければGateを通さない(推定しない) |
| 財務データ | SEC EDGARのXBRL(companyfacts)。**提出日が基準日より前**のものだけを使用(先読み防止)。年次(10-K)のみ。取れない項目は「判定不能」で、推定で埋めない |
| 株価 | Yahoo Finance(yfinance、非公式)。日足。2016-06以降(dev用) |
| シグナル | 約21営業日ごと(月1回)。devは2017-07-03〜2026-03-31(105日) |
| 売買の仮定 | シグナル翌営業日の始値で買い、1・3・6か月(21・63・126営業日)後の終値で売る。片道0.10%のコストを往復で控除 |
| 比較対象 | ALL_GATE(Gate通過の全銘柄を等金額)、SIMPLE_RSI(RSI<30のみ)、SPY |
| 統計 | 日ごとの「グループ平均 − ベースライン平均」を、日付ブロックのブートストラップで区間推定(3か月はリターン期間が重なるためブロック長3日付) |

**Timing(v1、V2・V2bでも同一)**: RSI14、20/50/200日線、直近高値からの下落率、出来高比、SPYとの相対比較で100点満点のスコア。Red Flag(長期下降トレンド、銘柄固有の弱さ、高値から40%超の下落、5日で15%超の急落)があればA/Bにならない。シグナル種別はPULLBACK / OVERSOLD / MARKET_DIP / RECOVERY。Timing高 = v1判定のAまたはB。
**判定表(V2・V2b)**: A = Quality HIGH かつ Timing高 / B = (HIGH×v1のC)または(MID×Timing高) / C = Quality判定不能(最高でもC)、またはMID×v1のC / D = Quality LOW またはv1のD。

## 3. V1（技術指標のみ）— 設計・結果・データ上の問題
- ルール: `rules_v1.yaml`(sha256 `d40847b9…`)を、バックテスト前にコミットして凍結。閾値は慣習的な値で、過去データに合わせた探索はしていない。dev(2017-07〜2022-12)とfinal(2023-01〜2026-03)に分割。
- **初回(619銘柄)**: A判定の平均は1か月+2.3%、3か月+5.6%、6か月+5.5%と良く見えたが、全銘柄ベースラインとの差は標準誤差の範囲内。Bの3か月対SPY超過は dev +1.0% → final −2.1% と符号が逆転した。**この final(2023-01〜2026-03)は1回使用済み**で、V1には再利用できない。
- **データ上の問題(原因と対処)**:
  1. 対象が619銘柄しかなかった。原因は、時価総額の取得が制限(アクセス過多)で失敗し、4,790銘柄中3,800銘柄分が空のまま保存されていたこと。→ 失敗分だけを少しずつ再取得する方式に変更し、成功率99.2%(4,787銘柄中4,751)になった。株価は対象3,138銘柄中2,978銘柄が成功、160銘柄は履歴不足(上場後1年未満)、失敗0。
  2. 株価の最終日が銘柄でずれる(再利用分と新規取得分)問題 → 最終日をそろえる処理を追加。
  3. 分割調整後の株価が極端な銘柄(逆分割を繰り返した銘柄)がGateを通る懸念 → 該当16銘柄(965行)を除いても3か月平均は2.55%→2.52%、6か月は4.96%→4.89%で、結果はほぼ動かなかった。
  4. 日次±80%以上の変動が466件(488銘柄)。出来高の急増を伴う実際の値動きが371件、分割記録と一致して調整漏れの疑いが1件、翌日に戻るデータ誤りの疑いが11件、分割記録の近くで比率が合わないものが15件、原因不明が68件。極端な上位リターンはNVAX(2020年)、AMC(2021年)など**実際の出来事**で、データ誤りが結果を支配している証拠は見つからなかった。**異常値の除外・補正は一切行っていない。**
  5. 実行環境(Colab)のリセットでデータが消える問題 → 保存先をGoogleドライブに変更。
- **全2,978銘柄での再実行(devのみ、ルール不変)**: Gate通過86,774行・66日。Aの対ベースライン超過(日単位、95%区間)は1か月 −0.5% [−1.3, +0.3]、3か月 −0.1% [−1.3, +1.0]、6か月 −0.7% [−2.4, +1.1]。頑健評価(1日10件以上の日のみ)でもAの3か月は +0.4% [−0.8, +1.7]、中央値差 −0.2%で、**全グループの区間が0をまたいだ**。Aのコホート最大DDは−37.8%で、ベースライン(−30.6%)より悪かった。
- V1の限界: 時価総額の推定が「現在の株式数×当時の株価」で、その後に大量発行した銘柄(例: AMC)が当時$1B超と誤判定される歪みがあった。これがV2以降の時価総額の定義変更の理由。

## 4. V2 — 設計・事前登録した判定基準・結果
**変更点**: Quality(5項目×20点)を追加し、時価総額を当時の発行済株式数で計算。Timingはv1のまま。
- Quality(V2): 売上成長率、営業利益率、FCF率((営業CF−設備投資)/売上)、自己資本比率(株主資本/総資産)、株式の希薄化(1年変化率、分割は調整)。各項目を絶対値のしきい値で点数化し、70点以上=HIGH、45点未満=LOW。**1項目でも取れなければ判定不能(最高でもC)**。
- ルール: `rules_v2.yaml`(sha256 `9072ccf1…`)。dev実行のコミット `d9e3f16b…`。

**事前登録した成功基準**(`criteria_v2.yaml`、sha256 `8fa9e30a…`。一度コミットしたら変更しない。主要検証はQuality高×Timing高(V2_A) vs ALL_GATE、3か月後、V2_Aが1日10件以上ある日のみ、採用日数40日以上):
- c1 平均差が+1%以上 / c2 95%区間の下限が0超 / c3 中央値差が0以上 / c4 暦年(採用日数6日以上の年のみ)の6割以上でプラス / c5 コホート最大DDがベースラインより5ポイント以上悪化しない(ちょうど5.0悪化も不合格) / c6 最終検証でも平均差が同じ符号(採用日数20日未満は「判定不能」)。
- 二段階評価: **Tier1**(全銘柄ベースラインに対して上の6基準)が主要な成功判定。**Tier2**(RSI単独に対しても同じ基準)は、Tier1を満たした場合にだけ評価する。

**結果(dev期間、2,974銘柄、Gate通過123,194行、105日)**:
| 基準 | 結果 |
|---|---|
| 採用日数 / 平均差 | 87日 / **+0.33%**（95%区間 −0.87〜+1.51%） |
| c1 / c2 / c3 / c4 / c5 | × / × / ○(中央値差+0.07%) / ×(プラスの年50%、対象8年) / ○(DD差+0.3pt) |
| 結論 | **Tier1を満たさない → 成功と主張しない（Tier2は評価しない）** |

参考(判定対象外): 3か月後の平均は、Quality高×Timing高 5.3%、Timing高のみ 4.8%、Quality高のみ 3.2%(全銘柄と同じ3.2%)、**Quality低×Timing高 5.1%**、RSI<30のみ 5.0%。Qualityによる上乗せはほぼ見られなかった。Qualityの判定可能率は2017年40%、2019年以降は約60〜64%。

## 5. V2b — 設計・事前登録・結果（最後の開発版）
**位置づけ**: V2の結果を見た後に設計された**2回目のdev試行**。このためdev成績は楽観的になりうる(独立した検証ではない)。V2bの変更内容と、最終検証に進む条件は、**実行前に固定**した(`docs/v2b_preregistration.md` sha256 `87e3fa14…`)。
- 変更は**Qualityの定義だけ**(他は完全に同一。ファイル差分とテストで検査)。V2の弱点(売上成長が成長であってQualityでない、利益率が資本で割られていない、「利益がキャッシュを伴うか」を直接測っていない、絶対値の点数でHIGHの割合が年で変動)に対し、確立された3指標の**同日・銘柄間の順位の平均**に差し替えた:
  - 収益性 = 営業利益/総資産(Novy-Marx 2013, Fama-French 2015) / 利益の質 = (純利益−営業CF)/総資産、低いほど良い(Sloan 1996) / 希薄化 = 発行済株式数の1年変化率、低いほど良い(Pontiff & Woodgate 2008)。
  - 上位1/3=HIGH、下位1/3=LOW。調整できる数値は「3分割」だけ。3要素のどれかが取れなければ判定不能。
- 追加の厳格化の記録: 「**V2の事前登録基準は変更しない。V2bはV2結果を見た後に設計された2回目のdev試行なので、偶然の合格を防ぐため、V2bのc2だけ97.5%区間という、より厳しい基準を追加する。95%→97.5%への変更は基準を緩めるものではなく、V2bに対する追加の厳格化である。**」(`criteria_v2b.yaml`、sha256 `b60122e2…`)。
- 最終検証に進む条件(事前固定): V2bが dev で (a) c1・c3・c4・c5 (b) Qualityの上乗せ(V2b_A − Timing高のみ、同日内、3か月後)が0超 (c) c2(97.5%区間の下限が0超、40日以上) の**すべて**を満たした場合だけ、V2bで最終検証を最大1回。満たさなければ最終検証は行わない。V2は devでTier1を満たさなかったので候補になれない。
- ルール: `rules_v2b.yaml`(sha256 `735b18d3…`)。dev実行のコミット `fb10677b…`。登録後はコードがルール・基準・事前登録文書の変更を拒否し、dev版は2つ(V2、V2b)に制限された。

**結果(dev期間)**:
| 基準 | 結果 |
|---|---|
| 採用日数 / 平均差 | 89日 / **−0.30%**（97.5%区間 −1.65〜+1.06%） |
| c1 / c2 / c3 / c4 / c5 | × / × / ×(中央値差−0.18%) / ×(プラスの年38%、対象8年) / ○(DD差+2.3pt) |
| (b) Qualityの上乗せ | **×**（−0.43%、97.5%区間 −1.44〜+0.53%） |
| 最終検証に進める条件(a)(b)(c) | **すべて ×** → **最終検証は行わない（封印のまま）** |

記述的な副次分析(選択基準には使わない): RSI<30の中でQuality HIGH − LOW = +0.82% [−2.63, +4.23](64日)、Timing高の中でHIGH − LOW = −0.46% [−2.83, +1.80](101日)。いずれも0と区別できない。
測定は改善した: Qualityの判定可能率は2017年50%、2023年以降は約73%。HIGH/MID/LOWは毎日ほぼ1/3ずつ。3か月後の平均は、V2_A 5.0%、Timing高のみ 4.8%、Quality高のみ 3.3%、Quality低×Timing高 5.1%、RSI<30のみ 5.0%で、V2と同様にQualityの上乗せは見られなかった。

## 6. 試した版の数と多重検定への対応
- dev期間で試したルール版: **V2、V2bの2版**。V2cは作らない(コードで強制)。V1は技術指標のみの前段階(別の期間設計)。
- V2bは、V2の結果を見て設計された。そのため(1)事前登録を実行前に固定、(2)c2を97.5%に厳格化、(3)Qualityの上乗せ条件(b)を追加した。
- 版の数は、結果を報告するときに必ず併記する。

## 7. 結論
**この方法(Timing: v1 / Quality: V2またはV2b)では、全銘柄を等金額で持つ方法を上回る優位性を示せなかった。** 事前登録した主要検証は、V2もV2bも、基準を満たさなかった。RSI単独の方法とも、有意な差は見られなかった。

## 8. 限界(必ず併せて読む)
1. **検出力**: 区間の半幅は約±1.2〜1.4%(3か月)。**それより小さい優位性は、実在しても見えない**。したがって「優位性がない」ではなく「示せなかった」が正確。
2. **生存者バイアス**: 現在の上場銘柄だけが対象。上場廃止銘柄の履歴はほとんど含まれない。古い期間ほど強い。絶対成績は実際より良く出る。
3. **年次の財務データのみ**: 10-K(年次)だけを使い、四半期(10-Q)の最新情報(TTM)は反映していない。最大で約15か月前の情報になる。
4. **判定不能が多い**: 営業利益が無い銘柄(金融機関など)や、XBRLの項目が揃わない銘柄は判定不能。Gate通過行のうちQualityを判定できたのは、V2で約60〜64%、V2bで約73%(2023年以降)。複数株式クラスの会社は、株式数が一部のクラスしか反映されない可能性がある。
5. **株価データ**: Yahoo Finance(非公式)の分割調整済み価格。調整の誤りは、異常値の監査で一部しか確認できていない(除外・補正はしていない)。
6. **コストと実行**: 片道0.10%のコスト仮定。流動性の低い銘柄のスリッページは過小評価の可能性。決算前除外は、バックテストでは未適用(過去の決算日が無い)。
7. **標本**: 月次シグナルの3か月・6か月リターンは期間が重なる。独立な標本数は「日数」に近い。MARKET_DIPなど特定の相場局面に集中するシグナルは、日数が少ない。
8. **期間**: dev期間(2017-07〜2026-03)は、強気相場が多く、特定の局面(2020年のコロナ急落と反発、2022年の下落など)の影響を受ける。
9. **多重検定**: V1・V2・V2bと設計を重ねている。V2bのdev成績は楽観的になりうる(これを補うため基準を厳格化したが、完全ではない)。
10. 6か月後は、全グループがSPY(時価総額加重)を下回った(例: ALL_GATEの対SPY超過 −1.1%)。等金額の中小型を含む全銘柄は、期間中のSPY(大型株主導)に劣後した。

## 9. 最終検証期間の取り扱い
- **2011〜2016年の最終検証期間(シグナル2011-01〜2015-11、結果は2016-05まで)は、一度も使用していない。** dev用データは2016-06以降のみで、最終検証用の株価は取得すらしていない(最終候補を凍結するまで取得できない仕組み)。
- V2もV2bも「最終検証に進む条件」を満たさなかったため、最終検証は**行わない**。この期間は封印のまま残る。新しい仮説を検証する場合のために、探索には使わない。
- (参考)V1のfinal期間(2023-01〜2026-03)は、不完全なデータ(619銘柄)で1回使用済み。V2・V2bのdevには、この期間が含まれる。

## 10. 通知Bot(候補リスト・監視ツール)の運用仕様
**位置づけ**: 優位性が示せなかったため、「勝てる銘柄」「高確率」などの表現は使わず、**条件に該当した銘柄を、判定根拠とともに一覧する監視ツール**として運用する。売買の推奨ではない。
- 判定ロジック: Timing=v1(`rules_v1.yaml`)、Gate・Quality・判定表=V2b(`rules_v2b.yaml`)を、バックテストと**同じ関数**で計算する(テストで一致を検査)。
- 通知の内容: ①Quality高×Timing高(最大10銘柄) ②Timing高だがQuality判定不能(最大5銘柄、判定不能と明示)。各銘柄に、終値、Timingのスコアと種別、判定の根拠(RSI、高値からの下落、50日線・200日線との差、出来高比、SPYとの差)、Qualityの3指標と同日順位、リスク(Red Flag、判定不能の理由)、次回決算日(2つの情報源を照合。取れなければ「取得できず(判定不能)」)を表示する。
- **決算前の扱い(運用時のみ・バックテスト未検証)**: v1に凍結した決算前ルール(決算まで7日以内なら評価を1段階下げて表示)を、そのまま使う。
- 取得できない情報は、推測で補わず「判定不能」「取得できず」と表示する。
- **記録**: 毎日、Gate通過の全銘柄について、判定日、終値、スコア、採用理由、Quality、決算日、ルールのバージョン(ハッシュ)、データ取得日、通知したか、を保存する。後から、通知した銘柄の実際の成績を、同じ日の全銘柄(ベースライン)と比べて検証できる。
- 変更の禁止: この報告書、V1・V2・V2bのルールと基準、Botの仕様ファイルは、ハッシュを記録して凍結する。起動時に検査し、一致しなければ実行しない。変更する場合は、新しい版の報告書として登録し直す。
